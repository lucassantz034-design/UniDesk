- (direction) User selected Coaching path for interactive architectural design
- (constraint) Architecture topology consists of two distinct domains: (1) Local On-Premise instance per company and (2) Centralized Cloud Control Plane
- (decision) License enforcement policy: Two-stage grace period. Stage 1: Restricted warning banner for local admins upon payment due. Stage 2: Total application lock if payment remains overdue past grace window
- (decision) Network protocol: Outbound HTTPS/TLS REST only from on-premise UniDesk instances to Central Control Plane; no inbound ports needed on client network
- (decision) Database strategy: Zero cost priority. Local UniDesk instances retain SQLite (embedded, high-performance, ). Central Control Plane uses free-tier PostgreSQL (Supabase or Neon free tier)
- (decision) Support architecture: In-app support module embedded inside UniDesk Local Admin Portal (Option A), submitting tickets and diagnostic telemetry payload directly to Central Control Plane
- (decision) Billing & Payment gateway: Asaas API with automated recurring subscriptions (Pix, Boleto, Credit Card) and webhook listener in Central Control Plane to update subscription state in real time
- (decision) Deployment flexibility: Client instance can run on-premise (local SQLite default) OR cloud-hosted (AWS/OCI/GCP/VPS) with remote database support (PostgreSQL/MySQL/RDS) via database adapter pattern
- (decision) Repository structure: Monorepo pattern. Central Control Plane placed within the same repository in a dedicated directory (e.g. /control-plane)
- (decision) Grace period duration: Exactly 15 days of restricted warning mode for local admins upon payment due; full application lockout enforced on day 16
- (decision) License Security Model: Pattern 3 (Asymmetric Cryptographic License Key + Instance UUID registration + Ed25519 signed JWT Heartbeats)
